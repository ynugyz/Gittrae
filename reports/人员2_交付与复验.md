## 3.2 本轮复核优化清单

对照交接要求逐项复核后完成的修正（均已被上述 18 项测试覆盖）：

| 问题 | 修正 |
|---|---|
| 方法口径变更后旧 `analysisId` 仍可能复用 | 新增 `METHODS_VERSION`，写入 `identity` 与结果 `methodVersion`，并参与 `analysisId` 计算 |
| `scopeId` 依赖记录顺序，输入顺序变化即换身份 | 改为 `scope:<hash({analysisId, filters})>`，不再使用记录顺序 |
| 范围快照把筛选值字符串化，丢失原始类型 | `normalizeFilters` 保留请求原值，比较时再用 `String()` 归一 |
| 同一字段多次排序 | 每字段只排序一次，median/q1/q3 复用 `quantileSortedType7` |
| 大数组 `Math.min(...values)` 有栈溢出风险 | 直方图 min/max 改为循环；箱线图仅排序一次并保留原始索引 |
| 数据集节点 ID 硬编码 | 优先复用 `bundle.graph.nodes` 中 `type === 'dataset'` 的 ID，找不到才回退 |
| 模型输出 Markdown 围栏导致解析失败 | `parseModelContent` 剥离 Markdown 代码围栏 |
| 空 `insights` 被当作成功 | 抛 `empty_insights`，代理返回明确失败 |
| 日志缺精确时间 | 日志与响应均带 `generatedAt` |
| `OPTIONS` 预检返回 204 但仍带 body | 204 响应体为空 |
| 重复 `recordId` 未被拒绝 | `assertBundle` 校验唯一性，重复抛 `duplicate_record_id` |

## 4. 接口说明与遗留

- `MetricResult` 在契约最少字段外增加 `reason`（`no_valid_values` / `insufficient_sample` / `constant_field` / `null`）与 `validCount`（由 `validRecordIds` 长度得到），便于界面解释空值。
- `exclusionReasons` 采用 `{ [recordId]: reason }` 对象；原因值目前为 `missing_value`、`non_numeric`。
- 数值型 `valueType` 接受 `number`、`numeric`、`integer`、`float`、`decimal`；`text`/`string` 等按非数值度量拒绝。
- `analysisId`、`scopeId`、`resultId`、`insightId` 均为确定性字符串；相同输入与参数得到相同身份。
- 当前 `src/contracts` 尚未建立（人员3 负责）；本模块以 ESM 导出对象，未另建第二套共享类型。人员3 接入时可补 TypeScript 声明，不改运行时结构。
- 未验证：页面联动、旧响应丢弃、三域真实数据、项目保存恢复；属人员3 集成范围。
- 真实调用失败时保留统计与图谱，代理返回明确错误码；不伪造 `valid` Insight。

# 总控应交成果

> **总控必读 · 交付要求。** 先读 [本角色入口](START_HERE.md) 与 [本轮完整必读清单](../README.md#control)；阶段和版本以 [仓库首页](../../README.md) 为准。首轮只读段落仅适用于首次接收，已有明确任务时使用后续阶段要求并如实填写状态。

首轮只交只读核对报告，按 [状态模板](STATUS_TEMPLATE.md) 报告；不得创建分支、写决策文件或提交代码。

明确进入后续阶段后，应交：

| 成果 | 内容 | 接收方 |
|---|---|---|
| 范围与接口决策 | 版本、决策原因、影响角色、是否需要更新共同样例 | 全体角色；人员3落实公共类型 |
| 阶段记录 | 统一起止时间、检查点实际结果、阻碍及责任人 | 三名开发、审计 |
| 集成安排 | 待集成提交、先后顺序、存在冲突和验证要求 | 人员3 |
| 问题分配 | 复现材料、责任开发者、验收标准、复验状态 | 原开发者与人员4 |
| 最终汇总 | 每项要求的实现/实测状态、证据位置、版本、未解决问题 | 用户 |

决策文件放在 `handoff/decisions/`，不要另写一套公共接口。需改共同契约时先明确决策，再由人员3统一落实相关类型、模拟数据和调用方。

交付必须区分“计划完成”“已经实现”“实际验证”。引用每位开发与审计的 commit 和报告位置；总控没有产品代码提交时明确写“无产品代码提交”，不要虚构成果。

# 人员3应交成果

> **人员3必读 · 交付要求。** 先读 [本角色入口](START_HERE.md) 与 [本轮完整必读清单](../README.md#person3)；阶段和版本以 [仓库首页](../../README.md) 为准。首轮只读段落仅适用于首次接收，已有明确任务时使用后续阶段要求并如实填写状态。

首次接收且尚未获开发任务时，只交 [只读状态报告](STATUS_TEMPLATE.md)，不创建项目、安装依赖、建立分支或编写公共类型。人员3现已获准开发并交付部分实现，详见 [本轮实现交接](IMPLEMENTATION.md)；完整产品与最终验收仍待上下游接入。

开发阶段应交：

| 成果 | 最低要求 |
|---|---|
| 共享骨架与契约 | 六个共同对象、可供另外两人使用的样例、统一启动方式与依赖锁文件 |
| 页面与统一状态 | 三域上传分析、统计三图、解释与错误状态 |
| 关系图与查询 | 合并基础/派生图，引用正确，数字和节点都可回源 |
| 项目保存恢复 | 导出后清空页面再导入，数据、选择、分析、解释与来源仍一致 |
| 集成版本 | 明确纳入的各角色 commit、构建/启动实际结果和遗留问题 |
| 复验交接 | 人员4可照做的启动、操作、验证步骤及证据位置 |

必须实际检查完整财务表的页面与图谱表现；小样例顺畅不能代表全量可用。集成检查不替代人员4的独立审计。

向总控交阶段状态与变更影响，向人员4交可启动版本和当前提交。产品代码在 `dev/app` 开发，`main` 的集成、提交与推送遵守根规则。根配置与公共类型发生变更后，及时通知受影响角色并更新同一份样例。

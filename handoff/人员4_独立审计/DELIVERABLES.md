# 人员4应交成果

首轮只交 [只读状态报告](STATUS_TEMPLATE.md)，不安装依赖、不创建分支、不修改代码、数据或验收材料。

明确进入审计阶段后，在 `acceptance/reports/` 交付：

| 成果 | 最低要求 |
|---|---|
| 验收矩阵 | 逐项对应共同标准，状态统一为 not_started / in_progress / passed / failed / blocked |
| 数据与统计报告 | 三域实际结果、固定样例核算、边界情况与覆盖缺口 |
| 来源与图谱报告 | 引用有效、计算可回查、条件切换一致性 |
| AI 实测记录 | 实际版本、调用时间、状态、分析编号及脱敏证据 |
| 恢复报告 | 导出—清空—导入的实测结果，ID/引用/数据一致性及密钥排除检查 |
| 缺陷与复验记录 | 复现步骤、证据、责任人、修复提交和复验结论 |

总报告必须写明被测集成 commit、数据 SHA 和使用的样例。未执行某项记为 not_started，因外部条件受阻记为 blocked，不能写“理论支持”或“应该可用”代替结论。

审计报告提交到 `audit/verification`。不得在审计分支修产品功能，也不得改变固定期望值来让测试通过；合入与推送遵循根规则。最终将报告交总控和人员3，产品问题同时指向对应原开发者。

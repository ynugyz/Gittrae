## 如何读到当前状态

先读公共规则，再读取接口负责人分支上最新状态文件和其绑定的代码commit；main上的同名文件可能尚未合入最新报告。若分支尚不存在或未推送记录，写“远程交付未确认”，不能断言别的电脑尚未开发。接口文件的报告commit可用GitHub文件历史或 `git log -1 --format=%H -- handoff/status/文件名.md` 取得。

每份报告分开写实现交付、开发者自测、下游真实联调、人员4独立复验。总控整理已存在报告时明确标注“转录开发者报告”或“已读审计报告”，不能把它们说成自己实测。

## 报告必填内容

接口ID/必要性/责任人；报告人/时间/分支；公共契约版本及批准记录；完整实现commit及成果路径；已完成/未完成；自测输入、操作、预期、实际及证据；真实联调commit与下游确认；人员4独立报告与受测commit；依赖和阻塞；下一步责任人、前置条件与验收条件。

状态仅用not_started / in_progress / passed / failed / blocked。未执行与受阻区分；MOCK、团队参考和真实产品实测区分。证据中的commit或契约变动时，受影响结论标记待复验，不能沿用旧passed。详细日志直接链接，勿整份复制。

## 什么时候更新

首次接手确认远程成果；形成可交接提交；发现或解除阻塞；公共接口发生变化；第20/60/90/120/150分钟检查点。微小编辑不要求重复汇报。实现者维护实现和自测；接手者追加联调；人员4仍只在acceptance/reports维护审计，总控和接口负责人链接其证据。

## 怎样决定下一步

| 当前事实 | 现在允许建议的动作 | 不能据此宣称 |
|---|---|---|
| 契约已确认，真实上游未交付 | 已授权的独立实现和明确标记的MOCK自测 | 已经真实联调通过 |
| 模块已提交并自测，依赖相容且可取得 | 下游按确切commit接入真实数据 | 产品已经独立审计通过 |
| 外部API或上游被阻塞 | 记录责任人与解除条件，继续不依赖它的已授权工作 | 用模板、旧缓存代替硬验收 |
| 集成完成，人员4尚未复验 | 固定集成commit并提交审计 | 整体签收通过 |
| 人员4在当前版本有完整通过证据 | 总控按硬验收逐项汇总签收 | 把其他版本或其他数据范围自动判为通过 |

每次裁决必须回答：是否首版必做；已做与未做的证据；直接依赖是否满足；现在由谁做什么；暂缓何项及原因；接手者如何验收。未完成的必做项必须保留，范围外需求不自动增加。

## GitHub使用约定

本目录初始结构由总控在docs/control维护，各角色在自己的模块分支更新负责文件，并在提交/PR中附接口ID。索引只登记固定路由，动态状态以各独立文件及其源commit为准。多分支冲突需核对来源，不盲目整文件覆盖。

初始规则通过文档PR进入main后，各角色接手时读取；本目录不代表已自动通知其他对话，也不自行安排定时检查。新增接口报告只覆盖协作记录，不修改公共接口语义、产品代码或验收要求。

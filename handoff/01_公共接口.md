# 公共接口 v1.0

> **全员必读。** v1公共设计。接入时必须对照人员3已实现类型；待决定项仍须总控定稿，不能把实现细化或建议当成已批准变更。 先核对 [仓库首页](../README.md)，并按 [交接必读总索引](README.md) 阅读本角色新增材料。

这是首次交接的v1公共契约设计，不能仅凭本文断言全部类型或函数已经实现。人员3现有共享类型、模块入口与未定事项见 [实现交接](人员3_界面与集成/IMPLEMENTATION.md)。总控决定接口变更，人员3统一编码；其他角色不复制私有版本。

## 1. 共同约定

- `schemaVersion` 首版固定为 `1`；时间使用 ISO 8601 字符串；路径使用仓库相对路径及 `/`。
- JSON 数值只能是有限 number 或 `null`；不能传 `NaN`/Infinity。缺失值为 `null`，零和负值保留。
- 指标单位独立记录；百分数字段用百分数点，如 `5.18` 表示 `5.18%`。百分号原文本保留在来源中，不一律再乘100。
- 股票代码、地区名称、厂商名称和排名角色明确区分；标识不能因看似数字而被当作度量指标。
- `SourceRef = { sourceId, recordIndex, columnIndex }`：`recordIndex` 从1开始、不含表头，按解析后的CSV记录计数；`columnIndex`从0开始。引号内换行不是新记录，空记录的位置仍保留；清洗过滤不能重编号来源。
- 每个规范单元格可引用多个 SourceRef；未得到来源支持的派生值必须记录明确变换及其输入，不能伪装原始单元格。
- 原始文件按字节SHA-256标识，不能按文件名识别相同内容。重复上传同内容复用来源身份，文件名作为展示别名。
- 规范数据版本由源指纹、有序字段映射、适配器版本及转换参数确定；分析编号绑定数据版本、规范化筛选与方法版本。相同输入和参数产生稳定身份；不同筛选不得复用旧分析。
- ID为字符串；关联用ID，不能用界面顺序或显示名称。由源模块产生ID，下游保留，不重新编号。

## 2. 对象与最少字段

以下字段名是交接约定。枚举中的英文只用于代码，页面以中文展示。

### DatasetBundle：人员1产出

| 字段 | 内容 |
|---|---|
| schemaVersion | 1 |
| datasetId / datasetVersion | 规范数据身份与版本 |
| domain | `D1`、`D2`、`D3`、`generic` |
| adapterType / adapterVersion | `nbs-regional-wide`、`eastmoney-financial`、`gasgoo-ranking`、`cpca-table`、`generic-csv`及版本 |
| sources | SourceFile数组，保存sourceId、原文件名、sha256、encoding、parseOptions、headers、rawRecords、rawBytesBase64；parseOptions记录分隔符、引号规则及空记录保留方式；rawRecords为表头之后原始字符串记录，原字节另存以便导出恢复 |
| fields | Field数组：fieldId、label、role、valueType、unit、meaning、definitionStatus、analysisPolicy；role为identifier/dimension/measure，definitionStatus为confirmed/unknown；analysisPolicy为allowed或excluded，excluded必须附exclusionReason |
| records | Record数组：recordId、values（fieldId→string/number/null）、provenance（fieldId→SourceRef数组） |
| transformations | 转换记录：transformId、type、inputSourceIds、说明、受影响字段及数量；包括宽转长、过滤、连接、单位变换和重复键问题 |
| issues | Issue数组：code、severity、message、可选fieldId/recordIds/sourceRefs；severity为info/warning/error |
| graph | 人员1的GraphFragment |

一份Bundle代表一种有明确分析单位的规范表；多文件可合成一份Bundle，不能把厂商榜、车型榜和CPCA总量硬塞为同一观测表。导入返回多个Bundle也合法。D1宽转长生成的新记录仍指向原始年份列；来源数据永不覆盖。已知有问题的汽车环比字段保留来源，但analysisPolicy必须为excluded；界面禁选，统计层也独立拒绝，不能只靠一条警告。

### AnalysisRequest：人员3发起

`{ datasetId, datasetVersion, measureFieldIds, correlationPair, filters }`

- `measureFieldIds` 为需要描述统计的度量字段；`correlationPair` 为两个字段ID或`null`。
- `filters` 为 `{ fieldId, operator, values }` 数组，首版operator限 `eq`、`in`，各条件AND；同一条件多值按in处理。
- 默认年份、月份和市场筛选由适配配置提供，并在界面和scope中显式显示。用户操作生成新请求，不能静默跨期合并。
- C模块（人员2）拒绝未知字段、数据版本不一致、非数值度量或analysisPolicy为excluded的字段。跨表对齐在人员1适配层完成，统计层不擅自连接记录。

### AnalysisResult：人员2产出

| 字段 | 内容 |
|---|---|
| schemaVersion / analysisId | 1；当前计算身份 |
| datasetId / datasetVersion / request | 固定输入版本和请求快照 |
| scope | scopeId、过滤条件、选中记录ID、范围标签及限制 |
| results | MetricResult数组 |
| chartData | 直方图、散点图、箱线图的预计算数据；包含结果引用及记录引用 |
| issues | 样本不足、常量列、不可计算等说明 |
| graph | 人员2的GraphFragment |

MetricResult至少包含：`resultId`、`metric`、`fieldIds`、`value`（number或null）、`unit`、`method`、`parameters`、`validRecordIds`、`excludedRecordIds`、`exclusionReasons`。`validCount`由有效ID长度得到，不能与ID列表不一致。每个统计量可以有不同的有效样本；相关性使用两字段同时有效的记录。

统计结果保留计算精度，显示格式由界面处理，显示舍入不能反写计算值。`resultId`确定性地位于analysisId命名空间内。

chartData固定为以下结构，人员3不得另算分箱、四分位或样本筛选：

- `histograms`：数组，每项 `{ fieldId, edges, counts, binRecordIds }`。edges长度为counts长度+1；binRecordIds与counts逐箱对应且数量一致。全缺失时三个数组均为空。
- `scatter`：`null`或`{ xFieldId, yFieldId, correlationResultId, points }`；points为`{ recordId, x, y }`数组，只包含成对有效记录。
- `boxplots`：数组，每项`{ fieldId, lowResultId, q1ResultId, medianResultId, q3ResultId, highResultId, outliers }`。low/high引用实际观测须线的MetricResult；outliers为`{ recordId, value }`数组。无有效值时相应MetricResult.value为null，界面显示空状态。
- 三者均属于父AnalysisResult.analysisId。分箱与散点点击使用recordId及字段映射回源，统计值使用resultId回源。

### GraphFragment / GraphSnapshot：三方共享

`GraphFragment = { schemaVersion: 1, owner: 'data' | 'analysis' | 'insight', nodes, edges }`。

Node最少包含：`id`、`type`、`label`、`ref`；ref保存真实对象ID。type固定为 `source/dataset/indicator/scope/calculation/finding`。

Edge最少包含：`id`、`from`、`to`、`type`。首版只允许以下方向和语义：

| 边类型 | 方向 | 产生者 |
|---|---|---|
| derived_from | dataset→source | 人员1 |
| contains | dataset→indicator | 人员1 |
| selects | scope→dataset | 人员2 |
| uses_scope | calculation→scope | 人员2 |
| uses_indicator | calculation→indicator | 人员2 |
| cites | finding→calculation | 人员2（确定性事实及AI解读） |

calculation节点与MetricResult一一引用，固定ID为`calculation:${resultId}`；scope与筛选快照对应。finding引用Insight，固定ID为`finding:${insightId}`；每条引用边ID为`cites:${insightId}:${resultId}`，目标为相应calculation节点。记录明细通过SourceRef查询，不创建每行每格图节点。scope的年份/地区/行业标签用于可见解释。

人员3合并GraphFragment为GraphSnapshot，检查ID冲突、引用存在性和允许的边类型；相同ID与相同内容可去重，不同内容同ID必须报错。不得因界面需要编造关系。图默认展示当前分析的邻域；历史分析保留但不混入当前解读。

### Insight：人员2产出

`{ insightId, analysisId, kind, origin, textTemplate, resultRefs, generatedAt, model, status }`

- kind：`fact` 或 `interpretation`；origin：`computed` 或 `live_ai`。
- textTemplate允许使用 `{{result:resultId}}` 数字占位；resultRefs列出所有被引用的resultId。程序插入对应显示数值和回源操作。
- 模型不重新编写统计值。未知、跨分析或占位缺失引用均为校验错误，不能显示为通过；结论范围必须受输入限制。
- status：`valid`、`invalid`；接口失败保存在请求错误状态，不伪造一个valid Insight。
- model在live_ai时记录实际返回的模型名，computed时为null。generatedAt记录实际生成时间。历史记录恢复后仍保留来源及时间。

### ProjectSnapshot：人员3产出

`{ schemaVersion: 1, projectId, createdAt, savedAt, datasets, analyses, insights, selection }`。

datasets为DatasetBundle数组，analyses为AnalysisResult数组；selection保存当前datasetId、analysisId、选中指标和节点。GraphSnapshot由datasets中的基础图、analyses中的派生图和insights重建，不作为独立事实真值。Insight本身不另存graph；恢复时按照上述固定finding与cites ID规则，逐个valid Insight及其resultRefs重建发现图，校验后合并，再恢复当前选中节点。API返回的发现图也必须遵守相同规则。

导出包含原始字节、来源位置、规范数据、分析和解释，文件后缀 `.t3project.json`。不包含密钥、服务端环境、绝对路径和聊天上下文。恢复时核对版本、原字节hash和引用完整性，并按保存的encoding与parseOptions重解析原字节，要求headers/rawRecords缓存与重解析结果一致；不一致拒绝恢复。保留ID，不自动重新计算分析、不自动调用模型；不支持版本或损坏引用给出错误。这里的完整性检查用于防止损坏和缓存错配，不代表项目内容获得数字签名认证。

## 3. 模块调用边界

| 所有者 | 接口 | 结果 |
|---|---|---|
| 人员1 | `importFiles(files, options)` | Promise<DatasetBundle[]>；options包含适配器选择、字段映射、单位确认 |
| 人员2 | `analyze(bundle, request)` | AnalysisResult；纯计算，无文件系统与模型副作用 |
| 人员2 | `buildFacts(analysis)` | computed Insight[]及对应finding图分片 |
| 人员3 | `mergeGraph(fragments)` | GraphSnapshot或明确引用冲突 |
| 人员3 | `getEvidence(resultId)` | 当前项目中的方法、筛选、有效/排除记录、原始字符串与位置 |
| 人员3 | `exportProject / importProject` | 项目JSON下载或经校验恢复的状态 |

接口桩由人员3根据本契约建立；空状态明确返回未准备，不能生成看似真实的成绩。模拟数据必须有mock标记，并且不作为真实API证据。

## 4. 本机模型接口：人员2实现

`POST /api/insights`。请求：`{ analysisId, facts, context }`；facts为当前分析MetricResult的最小投影（resultId、metric、value、unit、method、样本数），context含字段意义、范围、已知限制。不传完整原始数据。

成功：`{ analysisId, requestId, insights, graph, model, generatedAt }`；失败：`{ analysisId, error: { code, message, retryable } }`。HTTP错误和JSON解析错误均不能被包装成成功。model返回格式按官方JSON输出能力验证，成功后仍需应用级引用校验。

本机代理读取环境变量 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`（默认https://api.deepseek.com）、`DEEPSEEK_MODEL`（默认deepseek-flash）。服务绑定127.0.0.1，开发期浏览器通过统一代理路径访问。人员3维护启动脚本和端口，人员2提供路由实现与环境示例；真实密钥不出现在示例中。

请求超时默认60秒，不自动无限重试；用户可手动重试。界面仅接受当前analysisId对应返回，过时响应保留为历史或忽略，不覆盖当前分析。AI失败时统计、网络和回源继续可用，但实时AI验收不通过。

## 5. 统计约定

- 描述统计逐列删除缺失；样本标准差分母为n−1，n<2为null。
- 四分位数采用线性插值（type7）；箱线图1.5IQR，须线落在阈值内最远实际观测点，异常点保留recordId。
- Pearson按成对有效数据；n<2或任一列常量时null并说明原因。
- 直方图10等宽箱，左闭右开、最后箱含右端点；常量范围按[value−0.5,value+0.5]；无有效值返回空分布及原因。
- 不静默去重、填零、去极值；发现重复连接键先阻断合并并报问题。统计结果必须能复算。
- 自建样例见[验收目录](../acceptance/fixtures/README.md)。官方真值缺失，不能宣称已对官方标准答案验收。

## 6. 变更和冻结

本契约是v1交接基线。角色首轮仅列出疑点，不能擅改；总控记录决定，人员3同步契约实现与所有样例，再通知各角色。变更要写影响的数据、模块及复验场景。150分钟首版不引入第二套类型体系或各模块各自的项目存储。

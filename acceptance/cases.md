# T3 验收用例

本文件规定未来产品的验收，不代表产品已经实现或测试通过。当前提交是交接材料。所有产品用例初始状态为 `not_started`；只有对指定 commit 实际执行并留下证据后，才可改记为 `passed`。

## 1. 状态、证据与复验

允许状态：`not_started`（未执行）、`in_progress`（正在执行、尚无结论）、`passed`（实测通过）、`failed`（实测不符合）、`blocked`（外部条件缺失，不能完成）。没有模型账户、额度或网络时，AI 用例是 `blocked`，不能按模拟输出记为通过。

每次验收记录：用例编号、代码 commit、输入数据路径与 SHA-256、分析编号、操作步骤、预期、实际、证据位置、状态、责任人。证据可为截图、无密钥的响应摘要、导出文件的校验结果或独立计算结果。截图本身不能证明统计值正确。

问题单统一格式：`编号／严重程度／复现步骤／预期／实际／证据／负责人员／修复 commit／复验结果`。阻断级问题包括数值错误、来源错误、实时 AI 未成功、三类数据任一不能走通、保存恢复丢失引用。由对应开发者修复，人员4在新 commit 上复验。

## 3. 统计核验方法

- 小型样例按 [fixtures/expected.json](fixtures/expected.json) 逐项核对，绝对误差不超过 `1e-9`；计数、频数、ID和null状态须完全相等。
- 真实样例用独立Python或电子表格计算核对，记录工具和口径；团队浮点容差为 `max(1e-6, abs(reference) * 1e-9)`，显示舍入另行比较。该容差是团队约定，不是缺失官方真值的替代声明。
- 原包缺失官方expected_stats文件，不能把来源说明中的示例数字或本团队结果标成官方gold。
- 样本标准差使用 `ddof=1`；四分位采用Type 7线性插值；Pearson只用两字段同时有效的记录。空字符串、不可解析值和无穷值不得作为零。
- 直方图10等宽箱，区间左闭右开，最后一箱包含最大值；箱线图须区分1.5 IQR界限与界限内最远的真实观测值。
- 引用位置使用解析后的数据记录序号（recordIndex从1开始，不含表头、计入空记录）和列位置（columnIndex从0开始）；规范化排除空记录后不重编号。含引号换行时不得以物理文本行号替代。
- 常量值直方图区间扩展为[value−0.5,value+0.5]再分10箱；全缺失字段的直方图为空。

## 4. 三域完整流程记录

每个域单独填写一次：输入文件与SHA → 适配后的字段/单位 → 筛选范围 → 统计结果 → 三类图 → 真实AI响应摘要 → 三处回源 → 项目保存恢复。人员4从原始CSV独立抽查，不只检查开发者给出的截图。

实时调用证据只保留请求时间、服务商、模型、响应状态、分析编号和解读引用；不得记录Authorization、密钥或完整敏感配置。历史解释需标记历史时间，不能替代AI-01的新请求。

## 5. 审计报告格式（待产品可运行后填写）

报告存入 `acceptance/reports/`，以日期与受测commit命名。字段：受测commit、环境、输入版本、用例结果表、阻断项、非阻断项、修复与复验记录、尚未执行的项目、最终结论。最终结论只取“通过／未通过／条件不足未完成”，逐项给依据。不得提前创建全绿报告。
